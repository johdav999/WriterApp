# Local collaboration with two real Prosa accounts

The explicitly enabled local Staging profile runs the normal Prosa interface at **http://localhost:5398/app/collaboration** by default. If that port is busy, the launcher selects the next available port and prints the actual URL. Normal Development and Production defaults remain closed. Existing native packages are unchanged. The earlier diagnostic workspace remains at `/collaboration/test`, including its real-account sign-in form.

Start from the repository root in PowerShell:

```powershell
./scripts/start-local-collaboration.ps1
```

The script checks availability by binding IPv4 and IPv6 loopback listeners. It prefers app port 5398 and worker port 1234, automatically advances past occupied/reserved ports, and always chooses distinct ports. It checks again after building. Optional `-Port 5400 -CollaborationPort 1240` sets different preferences with the same automatic fallback. The selected ports configure Kestrel, the worker's backend and WebSocket URLs, allowed origin, public links and sign-in redirects. Both browsers must use the same printed app URL.

The script restores the server/client dependency graph for the current SDK and Windows account, checks/builds the editors and shared schema, then builds the server and starts an owned hidden process. Restore assets and output are isolated per Windows profile and initial selected app port beneath each project's `artifacts/local-collaboration-build/<profile-hash>/<port>/{obj,bin}`. This prevents another account's package-cache paths from contaminating the launch and avoids overwriting DLLs held by another running instance. `-SkipBuild` reuses only this account's existing build for the selected port; run without it once after an SDK/cache change or when that build is missing. A failed restore stops before build/launch and reports the NuGet recovery step. The .NET host starts and owns its Node collaboration child. Startup applies migrations only to `artifacts/local-collaboration/writerapp.db`; this profile overrides supplied database settings to that separate path. Keys and the database remain shared in that folder. Each launch's logs, asset manifest and process record are under `instances/<app-port>/`; `instance.json` at the root points to the latest launch. Sharing, custom durable commits, conversion, projections and presence are enabled for this profile. A server-issued schema-matching capability opens the journaled editor; the generic product editor gate stays closed elsewhere.

1. Use separate Edge and Chrome profiles, with one real Prosa account in each. If needed, sign in at `/collaboration/test`, then open `/app/collaboration` in the same browser. Two windows sharing cookies are one account.
2. Open **Shared** in the normal navigation. Existing local test manuscripts appear under **Your shared manuscripts** or **Shared with you**.
3. To share another local manuscript, open it from **Projects**, choose **Share**, finish syncing other devices and explicitly enable sharing. The retained-source conversion is irreversible from the old editor; conflicting source content stops conversion for recovery.
4. In **Share**, enter the collaborator's Prosa email, choose **Editor** or **Viewer**, and choose **Create invitation**. Both accounts must have signed in to this build at least once so the trusted provider identity can be resolved. Unknown or ambiguous addresses are rejected.
5. The other account opens **Shared**, then chooses **Accept** beside the named manuscript. No invitation ID, code or email delivery is needed. Discovery refreshes every 15 seconds; **Refresh access** checks immediately.
6. Type in both normal live editors. Confirm each sees the other's writing and **Saved to shared manuscript**. Reload and confirm both edits remain.
   Both browsers must open the same manuscript link. The diagnostic creator makes a separate manuscript on each new creation, even when the titles match. Match the **Manuscript** reference shown in Shared and above the editor; the Shared search also accepts this reference. A viewer receives updates but cannot type.
7. In the owner's **Share** page, choose **Viewer** or **Revoke access**. The affected manuscript closes while sign-in and other manuscripts remain available. Reopen after a role change. Viewers receive live committed updates without editing controls.

Shared manuscripts now open in the existing full `DocumentEditor`, with its normal toolbar, navigation, writing panels, preview and page selection. Its existing `PageEditor`/`SectionEditor` mounts the durable Yjs binding; it never performs legacy HTML autosaves. The old `/app/documents/{id}/live` route redirects to the normal document route. Page switches flush the current journal and mount a separate page binding. Live text updates refresh the normal local preview cache. Export/print/preview requests now attach a committed structure/page vector; selection export remains unsupported. These consumers still require authorized server access.

This is not complete parity for every tool. Checked AI Apply/history, whole-page version restore, legacy metadata/structure changes and unsupported content formats remain fenced. The conversion screen discloses these limitations. Their writers must be migrated before those features can be enabled; do not remove the legacy database/save fences. The local profile provides a test license view without changing stored subscriptions. Hosted manuscripts are not imported automatically.

Full-editor evidence is under `artifacts/realtime-full/` and `artifacts/full-editor-{build,browser,node}.log`. The browser fixture exercises the actual normal editor with isolated authentication and real collaboration services: two-way edits, reload, separate page journals, normal bold/headings, toolbar undo/redo, viewer live updates through projection delays, and revocation without logout. It does not establish advanced-tool parity or production acceptance.

Sign-in uses the existing native public-client registration, authorization code with PKCE, a protected per-browser correlation cookie and the registered localhost loopback redirect. The server validates token signature/issuer/audience/lifetime and the native delegated tenant/client/scope contract, strips token roles and issues a local HttpOnly session cookie containing claims, not access tokens. It requests no refresh token. Cookies expire with the validated token; sign in again when required. The listener and request boundary accept only loopback and the exact local origin. No cloud app registration or deployment is changed.

Stop after local saves finish:

```powershell
./scripts/stop-local-collaboration.ps1
# Or stop a specific owned instance using the port printed by its launcher:
./scripts/stop-local-collaboration.ps1 -Port 5399
```

The stop script defaults to the latest launch and checks the recorded PID, exact local URL in its command, and start time before terminating its owned process tree. `-Port` selects that instance's record, preserving other running instances. The database and browser journals remain for restart. A restarted Node worker may need the existing lease's remaining lifetime (up to 30 seconds) before a writable room becomes available. Unsaved local errors keep the editor/recovery queue alive and trigger the browser's leave-page guard; do not force-close a page reporting unsaved writing.

Verification: `artifacts/normal-sharing-build.log`, `normal-sharing-tests.log`, `normal-sharing-browser-tests.log`, `normal-sharing-regression.log`, and `artifacts/realtime-normal/`. The normal-interface browser fixture loads the actual WASM app and shared components against real Kestrel/Node/SQLite, with isolated synthetic authentication and shell data: explicit legacy conversion, email invitation, inbox acceptance, two-way typing, durable reload, viewer projection updates and revocation without sign-out. It requires the current local build running on port 5398 for static assets (override `PROBE_CLIENT_URL` if needed). Actual provider sign-in and the user's real two-account acceptance remain separate human checks. Earlier diagnostic evidence is retained in `artifacts/realtime-local/`.

Revoking access closes only the affected shared manuscript. The collaborator stays signed in, keeps their library and private local draft, and can open and edit their own manuscripts. Role changes also leave the library available so the user can reopen with the new role.

### Reordered updates and two-account sync follow-up (2026-10-19)

The isolated editor receiver was validating each delta as if it were a complete snapshot. A delta arriving before its dependency therefore failed with `collaboration_state_incomplete`. It now buffers dependency-incomplete deltas separately, deduplicates them through Yjs, caps the buffer at 16 MiB, and validates the combined document before applying it to the editor. Incomplete data never enters visible content or exported snapshots. Unsupported resolved content is rejected and its deferred batch cleared so later valid updates can proceed. The committed-state and journal validators remain strict.

All **22** checks in `WriterApp.Client/tests/verify-collaboration.mjs` passed against both rebuilt web/device bundles. The reordered test covers reversed inserts/deletes, duplicates, intervening local edits, unchanged snapshots while dependencies are missing, and no remote echo. An additional regression covers deferred unsupported content and subsequent recovery. Evidence: `artifacts/reordered-update-verification/browser-results.json`.

The normal full-editor probe now checks both directions of typing, concurrent edits, exact HTML equality, durable save status, and reload in both independent owner/editor browser contexts. `PROBE_SYNC_ONLY=1` runs this focused path without the later AI/structure-tool workflows. It passed through `NormalProsaWorkspaceEmailInboxAndLiveEditing` with real Kestrel/SQLite/Node services and isolated synthetic authentication. Evidence: `artifacts/two-account-sync-focused.log`, `artifacts/two-account-sync/result.json`, `owner.png`, and `editor.png`. The socket viewer/downgrade/revocation test also passed. ### Participant display names (2026-10-19)

Remote cursor labels, their accessible names and the online roster now use the authenticated account's `UserProfile.DisplayName`. The internal authorization response supplies this presentation field; clients still send only cursor positions, and actor IDs continue to identify accounts internally. Missing names fall back to “Collaborator”. Names are bounded to 256 characters and inserted as plain text. The roster deduplicates connections by account ID, so two different accounts with the same display name remain represented. Web bundle version 10 refreshes the cursor rendering.

The ordinary developer build's obj/bin files are untouched. Database, keys and journal locations remain unchanged.

### Automatic port fallback (2026-10-21)

The occupied-port exception came from a fixed-port refusal in the launcher, with the same ports hardcoded in the server's host/origin boundary, OAuth redirect and Node child configuration. All now use the chosen local ports. The strict loopback and exact-origin checks remain enabled. Alternative app ports use separate session and PKCE cookie names so simultaneous sign-in flows do not overwrite one another.

Verification: the real launcher selected **5399/1235** while the existing **5398/1234** instance stayed healthy. Restore, editor/schema builds and server compilation passed; the new app returned 200 and its worker reported ready. Requests with the old origin or a different host returned 403. Stopping 5399 left the original host running, and a `-SkipBuild -Port 5399` restart passed. The original database path was retained. **31** focused .NET tests passed, including alternate-port PKCE redirect/token exchange and invalid host/origin/port rejection. PowerShell tests cover real occupied IPv4/IPv6 listeners, free-port preference, distinct worker selection, fallback configuration propagation, preservation of previous process records, and stop guards for mismatched port, port-prefix, process, start time and foreign origin. These checks verify local startup and configuration; no fresh real-account provider sign-in was performed for this change.
