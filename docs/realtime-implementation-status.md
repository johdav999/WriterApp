## Prompt 5 — durable commit, recovery and lease fencing

Implemented:

- Added `.NET CollaborationCommitService` and dedicated private lease/commit/checkpoint/storage-health endpoints. - Added `CommitAllowed` to durable session rows through SQLite migration `20261017184535_CollaborationCommitGrants` and SQL Server migration `20261017184551_CollaborationCommitGrantsSqlServer`. Regular Hocuspocus scope remains read-only for every connection, including a custom-commit session.
- The backend locks the document/session/page barriers and rechecks account, entitlement, owner, lifecycle, mode, generation, schema and grant inside the serializable transaction. It clears tracked preflight state before the second authorization read; a regression test changes a tracked entitlement between preflight and the transaction to prove that it cannot be reused. Both providers use EF execution strategies.
- Per-page database leases have a process UUID owner, monotonically increasing epoch and 30-second expiry. Acquisition/renewal and every append/checkpoint verify the lease. A second active owner is refused; expired epochs cannot renew; takeover advances the epoch and fences the old worker. Node renews through the room queue when less than 10 seconds remain and an eligible session is active.
- Commit stores immutable bytes/hash, derives installation/author from the session, checks the expected predecessor, and atomically adds update + independent receipt + projection outbox event while advancing the sequence. Matching identity/hash returns the original receipt, including after compaction. Different bytes under the same identity are rejected. Database failures roll back all rows and sequence advancement.
- Added `src/commits.mjs`: one room queue, bounded admission, temporary Y.Doc validation, explicit durable envelope parsing and receipt validation. It refuses unsupported fragments/schema/links, malformed updates, missing dependencies, scope/installation mismatch, updates above 512 KiB binary and resulting documents above 16 MiB. WebSocket frames remain capped at 1 MiB.
- Canonical mutation/broadcast occurs only after persistence. Node then sends `durableReceipt`; transport synchronization remains unrelated to save acknowledgement. Unknown persistence outcomes, apply failures, stale leases, sequence loss or invalid receipts quarantine the room and close peers for a committed-state reload. The raw sync-step-2/update paths remain blocked even with custom commits enabled.
- Added `WriterApp.Client/src/collaboration/server-schema.ts` and a reproducible Vite SSR schema build. The checked-in Node module `WriterApp.Collaboration/src/generated/schema.mjs` comes from the same rich schema, JSON validation and fingerprint implementation used by both editors; runtime Yjs is external and pinned once. No copied Node schema or DOM mock. Updated the live gate's message to reflect current availability, then rebuilt both shipped bundles.
- Checkpointing uses the room queue and current lease. Snapshot insert, pointer advancement and covered update deletion are atomic. Receipts/outbox/historical snapshots survive compaction. Node checkpoints every 64 commits, with interval 2 in tests. No projection worker or HTML backdoor was introduced.
- Added `/health/live` and `/health/ready`; readiness requires fresh private .NET schema/storage evidence, matching commit configuration and no current quarantined room. It is separate from per-update durability. Detailed contracts, local flags, recovery and later acceptance boundaries are in [the transport README](../WriterApp.Collaboration/README.md).
