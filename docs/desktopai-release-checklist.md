## Native Windows installation and upgrade run

Use an approved trusted package/test channel on a controlled Windows account with x64 Windows App Runtime dependencies. Preserve the complete prior isolated app-data directory while the app is closed. Record installed `Get-AppxPackage -Name Prosa.WriterApp.Desktop` identity/install path and actual running `WriterApp.Desktop` EXE path; inspect the package's embedded environment/backend/data path rather than assuming the default output ran. Confirm ordinary guest/offline writing before authenticating. Use authorized accounts and a native-bearer-capable backend; LocalDev web identity does not provide desktop MSAL tokens.

Test clean install, then a higher version with the same package family and approved stable signer over representative prior data. Record writing HTML and document/section/page/node/guide IDs; pending preset/history operation IDs; canon account/backend scope; cover hashes/provenance; approved before/after recovery records; exact migration backups. Confirm no reseeding and no changed authored fields after failure/retry, offline save, close/relaunch and upgrade. Inspect unresolved history delivery independently of confirmed saved writing. Do not reset/uninstall an existing writing container to make the test pass.

Exercise native sign-in callback, secure refresh, revoke/expiry, sign-out and real account/backend switch; old proposals/private canon/history/covers must become unavailable while local writing remains. Verify background/foreground save, cancellation and ignored late results, keyboard/drawers/selection/focus and readable error/results at 1280×720 and 1920×1080; screen-reader/high-DPI checks remain required. Select checked AI journeys, review/Dismiss/Apply/Undo/Redo/history retry, native cover export and reopen. Capture actual native screenshots separately from browser fixtures.

## Mac simulator and physical device run

Provide an authorized iOS public-client configuration through `ProsaIosAuthSettingsFile`: ClientId, approved authority/tenant, API scope/consent, callback `msauth.com.prosa.writer.ios://auth` and matching backend native bearer allowlist. Do not substitute the Windows registration. Keep bundle ID `com.prosa.writer.ios` and both signed app/MSAL Keychain groups from `Platforms/iOS/Entitlements.plist`. Use a reachable approved backend; the Windows package's loopback address is not a physical-device backend. See [native setup](device-development.md#desktop-ai-prompt-21--native-ios-identity-2026-10-04).

On a compatible Mac with Xcode and .NET iOS/MAUI workloads, build the real simulator target (`iossimulator-arm64` on Apple Silicon, `iossimulator-x64` on an Intel Mac) with explicit backend/environment/auth settings. Record the `.app` bundle ID/version/configuration, simulator/device OS and app-container path and actual installed/launched app. Execute system callbacks/cancel/resume, actual secure selection/Keychain refresh, sign-out/switch, cold restart, offline rich writing, touch/keyboard/accessibility and one checked review/Apply/history/reopen flow on normal isolated data.

For physical device use authorized signing/provisioning and `ios-arm64`; confirm the profile includes both Keychain groups and the device. Test an in-place higher-build update with the same bundle/team identity and backed-up prior data, comparing the same IDs/content/queues/private caches/recovery/cover bytes. Simulator results do not establish device acceptance; managed Windows compilation establishes neither. Preserve failure evidence and source backups without obtaining credentials or changing external registrations by workaround.
